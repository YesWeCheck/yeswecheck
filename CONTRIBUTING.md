# Contributing

Thank you for your interest in YesWeCheck! This repository holds the public, developer-facing side of the product: documentation, the OpenAPI specification, SDKs, integrations and examples.

## Ways to help

- **Report a problem** with the docs, an example or an SDK: [open an issue](https://github.com/YesWeCheck/yeswecheck/issues/new/choose).
- **Ask for an integration** you would like to see: use the *Integration request* form.
- **Improve the docs or examples**: pull requests are welcome, from typo fixes to new framework recipes.

For questions about your account, billing or a specific verdict, write to [contact@yeswecheck.fr](mailto:contact@yeswecheck.fr) rather than opening an issue: we may need details you should not post publicly.

## Pull requests

1. Fork the repository and create a branch from `main`.
2. Keep each pull request focused on one change.
3. Write in British English, and never include a real API key or a real person's email address. Use placeholders such as `ywc_live_xxxxxxxx` and `jane.doe@company.co.uk`.
4. Describe what you changed and why in the pull request.

By contributing, you agree that your contribution is released under the [MIT licence](LICENSE).

## Code of conduct

Everyone taking part in this project is expected to follow our [code of conduct](CODE_OF_CONDUCT.md).
